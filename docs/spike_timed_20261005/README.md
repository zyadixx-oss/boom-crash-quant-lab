# الجولة الثانية: نتيجة خروج زمني دون سقف ربح

**لم يظهر مرشح رابح مستقر.** هذه جولة بحث تكيفية بعد فشل نموذج الوقف/الهدف
الأول. شُغّلت768 تركيبة في التطوير، ثم جُمّدت الاختيارات قبل قياس نقلها إلى
Boom1000 وCrash1000. لم تُعدّل المصادر المجمدة للجولة الأولى.

| الاختبار المنقول | n | متوسط صافٍR عند0.10ATR | PF |
|---|---:|---:|---:|
| Boom1000 — CRT، وقف2ATR، خروج15 دقيقة | 505 | -0.103 | 0.807 |
| Crash1000 — CRT، وقف2ATR، خروج15 دقيقة | 484 | -0.102 | 0.812 |
| Boom1000 — ضغطBB، وقف4ATR، خروج1 دقيقة؛ احتياطي مرفوض | 3,803 | -0.021 | 0.592 |
| Crash1000 — CRT+Displacement، وقف4ATR، خروج5 دقائق؛ احتياطي مرفوض | 399 | -0.057 | 0.614 |

لا مؤهل في التطوير لكل رمز، وكل نوافذ التحقق المتحرك الست سالبة في المتوسط.
جميع بوابات النقل فشلت، وتصحيحHolm يخص هذه الجولة فقط. النتائج لا تصحح سلسلة
البحث التكيفي كلها ولا تثبت استحالة جميع الاستراتيجيات الممكنة.

ظهر ضغطBB علىBoom1000 موجبًا قليلًا عند تكلفةصفر:0.003738R. لكنه يصبح
-0.002512R عند تكلفة افتراضية0.025ATR، وفاصل متوسطه دون تكلفة يشمل الصفر.
حد التعادل في نموذج التكلفة هذا0.014954ATR فقط. لا توجد أفضلية موجبة مؤكدة
بعد تكلفة مقاسة أو تنفيذ فعلي. لا يُستنتج من ذلك سبريد تاريخي معين.

جُرّب أيضًا الاتجاه المعاكس للانفجار داخل التطوير، مع نفس مشاهداتCRT/الضغط؛
لا نسمّيه تحولًا هيكليًا جديدًا. إزالة سقف الربح تسمح بجني قفزات كبيرة في
المحاكاة، لكنها لم تنتج تفوقًا مستقرًا في العينات المختبرة.

R محسوب نسبةً إلى مسافة الوقف، والعائد والتراجع يفترضان مخاطرة توضيحية0.25%
من الرصيد لكل صفقة. أسعار الدخول/الخروج هي مسار مؤشر عام، والتكلفة افتراضية.
الربح المالي، bid/ask والتكاليف المقاسة، الملء الحقيقي والاختبار الأمامي:
**NOT TESTED**. `LIVE_TRADING=false`, `READY_FOR_LIVE=false`, `LIVE_ALLOWED=false`,
`OPENED_TRADES=false` دائمًا.

## الأدلة والحدود

- `selection.json` و`selection.sha256`: القواعد وبصمات المصدر والبيانات قبل التقييم.
- `development_grid.csv`: كل384×2 إعدادات في7 نوافذ تطوير/تحقق.
- `results.json`: المقاييس، إعادة أخذ عينات يومية وكتل7 أيام، خط الأساس،18 حالة
  حساسية لكل فرضية، أثلاث الفترة، نقاط السعر الخام، ATR وتركيز الربح.
- `independent_audit.json`: إعادة حساب مستقلة منM1 لكل5,191 صفقة نقل؛98,852 فحصًا
  وصفر اختلاف. يستثني أهلية الإشارات وخط الأساس وbootstrap والحساسيات والملء الفعلي.
- مصدر1000 موثّق في`data/spike_timed_transfer/`. كانت الفترة نفسها معروفة على500؛
  لذلك النقل ليس تأكيدًا زمنيًا أماميًا. لا يُفترض استقلال مولّدات المؤشرات.
- طلب تاريخ500 أقدم أعطى6170 دقيقة فقط بدل259200؛ موثق في`data/spike_timed_external/`.
  لم تُستعمل العينة القصيرة كاختبار كافٍ ولم يُملأ الجزء المفقود.
- جميع نتائج500 المعاد استخدامها استكشافية. فشل هذه الجولة لا يُصلح بتغيير
  الحدود بعد الاطلاع على1000 ثم تقديم العينة نفسها كتأكيد جديد.

## إعادة التشغيل

استخدمPython3.12 مع`requirements-research-lock.txt` وملفات المصدر ذات البصمات
المحفوظة. يلزم ملفا500 الأحدث من`data/spike_hunter/`، وملفا500 الأقدم من
`data/spike_payoff_external/`، وملفا1000 الخام والمطبّع من`data/spike_timed_transfer/`.
انظر تعليمات الجمع في الجولة الأولى وملف بيانات النقل. ملفات الأسعار وسجلات
الصفقات مفصلة محليًا، ومستبعدة منGit؛ الملفات الإحصائية وبصماتها محفوظة فيه.

```bash
export LIVE_TRADING=false READY_FOR_LIVE=false LIVE_ALLOWED=false OPENED_TRADES=false
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
python -m pytest
python scripts/run_spike_timed_study.py --stage evaluate
python scripts/verify_spike_timed.py
```

تكرار التطوير يجب أن يكتب إلى مجلد جديد، مع المحافظة على الاختيار الأصلي:

```bash
python scripts/run_spike_timed_study.py --stage develop --output work/timed_reproduction
python scripts/run_spike_timed_study.py --stage evaluate --output work/timed_reproduction
```

أي مرشح لاحق يحتاج قواعد مجمدة واختبارًا ورقيًا مستقبليًا جديدًا، وتكاليف
وأسعار تنفيذ مقاسة قبل ادعاء ربح مالي. نجاح اختبارات الكود لا يثبت هذه الشروط.
