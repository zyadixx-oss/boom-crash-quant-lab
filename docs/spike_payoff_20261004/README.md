# تفسير اختبار العائد وطريقة إعادة تشغيله

**القرار: لم تثبت استراتيجية رابحة.** نُفّذ البحث على Boom 500 وCrash 500 مع
بقاء `LIVE_TRADING=false`, `READY_FOR_LIVE=false`, `LIVE_ALLOWED=false`,
`OPENED_TRADES=false`. لا توجد أوامر أو حسابات تداول في هذا الاختبار.

## ماذا تعني النتيجة؟

ارتفاع احتمال وصول السعر إلى هدف لاحق لا يكفي: قد يتحرك السعر عكس الإشارة
ويضرب الوقف قبل وصوله. كذلك تختلف بداية القياس عن سعر الدخول بعد التأخير.
هذه الدراسة تقيس مسار صفقة محددة، وليس مجرد وجود قمة أو قاع داخل نافذة مستقبلية.

يوضح [تشخيص ترتيب الحواجز](target_order_diagnostic.ar.md) الفرق: في Crash
وصل السعر إلى الهدف خلال المدة في595 من2,259 حالة، لكن498 فقط وصلت قبل الوقف
وفق المحاكاة؛92 وصلت لأول مرة في دقيقة لاحقة بعد الخروج، و5 ملتبسة داخل
دقيقة الوقف. هذا تشخيص لاحق على سعر الدخول المتأخر، وليس إعادة تقدير لتعريف
الـlift السابق أو دليلًا على أن تعديل الوقف سيُصلح النتيجة.

| العينة الخارجية الأقدم | الصفقات | متوسط العائد الصافي R | CI95 | معامل الربح PF |
|---|---:|---:|---|---:|
| Boom 500 — دعم/مقاومة، وقف1ATR، هدف2ATR،15 دقيقة | 2,216 | -0.317 | [-0.371,-0.263] | 0.587 |
| Crash 500 — دعم/مقاومة، وقف1ATR، هدف2ATR،15 دقيقة | 2,259 | -0.304 | [-0.356,-0.250] | 0.603 |
| Crash 500 — CRT+MSS، وقف1.5ATR، هدف3ATR،5 دقائق؛ تشخيصي مرفوض | 341 | -0.105 | [-0.172,-0.034] | 0.673 |

R وحدة قياس بالنسبة إلى مسافة الوقف الأصلية، وليست دولارًا. PF هو مجموع
العوائد الموجبة مقسومًا على القيمة المطلقة للعوائد السالبة؛ أقل من1 يعني أن
الخسائر أكبر من الأرباح في المحاكاة.

لا تكفي أفضلية Crash السابقة في توقع حركة2ATR لتوصية دخول. نرفض الترقية
التداولية للنماذج المختبرة. لا يعني ذلك إثبات استحالة كل قواعد CRT الممكنة.
يمكن متابعة تحليل اختلاف «وصول الهدف» عن «الوصول قبل الوقف» بوصفه تشخيصًا
بحثيًا فقط. أي فرضية جديدة تحتاج بروتوكولًا منفصلًا وبيانات لم تستخدم في الاختيار.

## حدود إحصائية مهمة لهذه النتائج

- اختُبرت432 تركيبة لكل رمز داخل أول70% فقط. لم تحقق أي منها300 صفقة و30 يومًا
  نشطًا مع30 صفقة ومتوسط موجب في كل واحدة من نوافذ التطوير الثلاث.
- الاحتياطي التشخيصي في Boom اختير من بين النتائج المتاحة بعد فشل الأهلية:
  ضغط الشموع أعطى صفقة واحدة في التطوير، وصفقة واحدة في كل فترة تقييم.
  فاصل bootstrap المتطابق الطرفين لتلك الصفقة لا يقيس عدم اليقين في المجتمع؛
  **العينة غير كافية للاستدلال**، والنتيجة لا تدخل أي توصية.
- احتياطي Crash فشل أهلية التطوير أيضًا. لا يتحول إلى مرشح بمجرد أن يزيد عدد
  صفقاته في العينة الخارجية.
- العينة الخارجية فترة أقدم مستقلة زمنيًا؛ ليست اختبارًا أماميًا. آخر30% من
  الفترة الأحدث سبق فحصه في بحث تصنيف الحركة، ولذلك وُسم بأنه معاد الاستخدام.
- المقارنات مع خط توقيت آلي تخص متوسط العائد لكل صفقة، مع اختلاف عدد الصفقات.
  جميع قيم Holm المصححة للفرضيات الخارجية تساوي1؛ لم تنجح أي بوابة بحث.
- حتى دون التكلفة الافتراضية ظل المتوسط الخارجي لنموذج الدعم/المقاومة
  سالبًا: Boom=-0.217R وCrash=-0.204R. مع تنفيذ الوقف عند الحاجز وأولوية الهدف
  المتفائلة عند الغموض، دون تكلفة، بقي Boom=-0.168R وCrash=-0.153R.
- توقيت الخروج داخل الدقيقة غير معروف بدقة. التنفيذ الفعلي والتكاليف التاريخية
  المقاسة والربح المالي واختبار مستقبلي جديد: **NOT TESTED**.

## إعادة التشغيل على Python3.12

من جذر المستودع، بعد تثبيت `requirements-research-lock.txt`، عيّن الأعلام الأربعة
إلىfalse. ملفات الإدخال المطلوبة:

```text
data/spike_hunter/boom500_m1_clean.csv
data/spike_hunter/crash500_m1_clean.csv
data/spike_payoff_external/boom500_m1_180d_clean.csv
data/spike_payoff_external/crash500_m1_180d_clean.csv
```

توجد بصمات أول ملفين في `selection.json` وبصمات الملفين الخارجيين في سجلات
المصدر. لا تستبدل الملفات الأصلية بصمت إذا أعاد المصدر تاريخًا معدّلًا؛ سجّل
اختلافه وشغّل دراسة جديدة في مجلد مستقل. يمكن إعادة جلب الفترتين في مجلدين جديدين:

```bash
python scripts/collect_spike_history.py --days 180 --symbols BOOM500 CRASH500 --cutoff-epoch 1791112080 --output-dir data/payoff_recollect_recent
python scripts/collect_spike_history.py --days 180 --symbols BOOM500 CRASH500 --cutoff-epoch 1775560080 --output-dir data/payoff_recollect_external
```

بعد التحقق من البصمات، انسخ ملفات `*_m1_180d_clean.csv` إلى المسارات المطلوبة
أعلاه؛ احذف الجزء `_180d` من اسمي ملفي الفترة الأحدث فقط. يُرفض التقييم إذا
تغير كود الدراسة أو بروتوكولها أو البيانات الأحدث عن الاختيار المجمّد.
للتدقيق المستقل انسخ أيضًا ملفي الأسعار الخارجية الخام `boom500_m1_180d.csv`
و`crash500_m1_180d.csv` إلى `data/spike_payoff_external/`؛ يتحقق المدقق من
تطابق بصمتي الخام والمطبّع لهذه الفترة الخالية من الفجوات.

```bash
export LIVE_TRADING=false READY_FOR_LIVE=false LIVE_ALLOWED=false OPENED_TRADES=false
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
python -m pytest
python scripts/run_spike_payoff_study.py --stage evaluate
python scripts/verify_spike_payoff.py
python scripts/diagnose_spike_target_order.py
```

لتكرار مرحلة التطوير من الصفر استخدم مجلد نتائج جديدًا، ولا تكتب فوق الاختيار المحفوظ:

```bash
python scripts/run_spike_payoff_study.py --stage develop --output work/payoff_reproduction
python scripts/run_spike_payoff_study.py --stage evaluate --output work/payoff_reproduction
```

البروتوكول وبصماته يحافظان على نتيجة هذه الجولة؛ تعديل الإعدادات بعد قراءة
النتائج يحوّلها إلى بحث استكشافي جديد، ولا ينتج تأكيدًا مستقلًا.
